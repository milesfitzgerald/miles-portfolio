Teams ship agents they cannot measure

  • In expert-judgment domains — legal review, clinical documentation, financial analysis, design critique — nobody ever wrote down what good actually looks like
  • LLM-as-judge inherits the same blind spots as the system under test
  • Crowdsourced labels can't reach the judgment you're trying to automate
  • A rubric written in a planning doc encodes what someone assumed experts do, which is rarely what they actually do
  • What's missing isn't tooling. It's a defensible answer to: according to whom, and how would you know?

How I get to ground truth

  • Scope the judgment — find the decisions where the agent's output is accepted or rejected, and who does the accepting
  • Elicit from practitioners — think-aloud sessions with working experts on real cases
  • Code the transcripts — check agreement between raters; disagreement is data
  • Build the labelled set — validated ground truth with documented provenance
  • Hand over the harness — versioned and extendable, so it survives the next model swap
